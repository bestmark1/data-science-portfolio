## 📌 1. Постановка задачи и бизнес-контекст

В современных сервисах такси точное определение стоимости поездки напрямую зависит от прогнозируемого времени в пути. Поездки рассчитываются на основе фиксированной ставки и переменного тарифа (время + расстояние). 

**Бизнес-цель:** автоматизировать расчет стоимости поездки за счет точного предсказания времени нахождения такси в пути.

**Техническая задача (Data Science):** Построить модель машинного обучения (регрессия), которая предсказывает непрерывную числовую величину — `trip_duration` (длительность поездки в секундах).

**Метрика качества:** **RMSLE** (Root Mean Squared Logarithmic Error) — среднеквадратичная логарифмическая ошибка. Она штрафует за относительную погрешность и сглаживает выбросы:

$$RMSLE = \sqrt{\frac{1}{n}\sum_{i=1}^n(log(y_i+1)-log(\hat{y_i}+1))^2}$$

В качестве целевой переменной в процессе обучения использовался логарифмический таргет: $z_i = \log(trip\_duration_i + 1)$. Это позволяет свести расчет метрики к стандартной **RMSE** над логарифмированными данными.

## 📊 2. Данные и интеграция внешних источников

В работе использовался датасет объемом около **1.5 миллионов записей о поездках** со следующими базовыми характеристиками:
* `id` — уникальный идентификатор поездки.
* `vendor_id` — ID таксопарка.
* `pickup_datetime` / `dropoff_datetime` — время начала/окончания поездки.
* `pickup_longitude` / `pickup_latitude` / `dropoff_longitude` / `dropoff_latitude` — географические координаты начала и конца маршрута.
* `passenger_count` — число пассажиров.
* `store_and_fwd_flag` — флаг сохранения записи в память терминала.

### 🌐 Внешние источники данных (Data Enrichment):
Для достижения высокого качества прогноза базовый датасет был значительно расширен:
1. **Данные OSRM API (Open Source Routing Machine):** Добавлены реальные дорожные маршруты, включая дорожную дистанцию в метрах (`total_distance`), идеальное время поездки с учетом графа дорог (`total_travel_time`) и количество перекрестков/шагов маршрута (`number_of_steps`).
2. **Данные о погоде (Hourly Weather NYC):** Подключена почасовая метеорологическая информация: температура воздуха (`temperature`), видимость (`visibility`), скорость ветра (`wind speed`), осадки (`precip`) и погодные явления (`events` — снег, дождь, туман).
3. **Праздничные дни США:** Календарь официальных праздников для выделения нерабочих дней (`pickup_holiday`).

## 🛠️ 3. Проектирование признаков (Feature Engineering)

Генерация признаков стала решающим фактором в улучшении метрики на Kaggle. Были разработаны и добавлены следующие группы фичей:

* **Временные признаки:**
  * Извлечены `pickup_date`, `pickup_hour`, `pickup_day_of_week`, `pickup_month` и бинарный флаг выходного дня `is_weekend`.
  * Интегрирован признак праздника `pickup_holiday`.
* **Географические признаки:**
  * **Расстояние Хаверсина** (`haversine_distance`) — кратчайшее расстояние между точками на сфере.
  * **Манхэттенское расстояние** (`manhattan_distance`) — расстояние между точками по ортогональной сетке улиц Нью-Йорка.
  * **Угол направления движения** (`direction`) — угол пеленга между стартом и финишем маршрута.
  * **Близость к ключевым транспортным хабам:** Рассчитаны расстояния до трех главных аэропортов Нью-Йорка: **JFK** (им. Кеннеди), **LGA** (Ла-Гуардия) и **EWR** (Ньюарк) как для точек посадки, так и для высадки.
* **Пространственная кластеризация:**
  * Координаты начала и конца поездок кластеризованы с помощью **K-Means (10 кластеров)** для автоматического выделения районов города (`geo_cluster`).

## 📉 4. Результаты и сравнение моделей

В ходе экспериментов было обучено и протестировано несколько классов моделей — от простых линейных до современных ансамблей градиентного бустинга.

### Сводная таблица метрик (RMSLE):

| Класс модели | Архитектура / Алгоритм | RMSLE (Train) | RMSLE (Validation) | Оценка поведения модели |
| :--- | :--- | :---: | :---: | :--- |
| **Линейные модели** | Linear Regression (Baseline) | 0.53 | 0.54 | Стабильный базовый уровень |
| | Polynomial Regression (deg 2) | 0.46 | 1.52 | 🚨 Критическое переобучение |
| | Ridge Regression (Regularized) | 0.48 | 0.48 | Хорошая регуляризация полиномов |
| **Деревья решений** | Decision Tree (default) | 0.00 | 0.57 | Переобучение "в пол" |
| | Decision Tree (Tuned, Depth=8) | 0.41 | 0.43 | Стабильное простое дерево |
| **Ансамбли** | Random Forest Regressor | 0.40 | 0.41 | Устойчивая модель без переобучения |
| | Gradient Boosting (sklearn) | 0.37 | 0.40 | Высокая точность, долгий расчет |
| **Бустинг (Продвинутый)** | **CatBoost Regressor** | 0.36 | **0.40** | Быстрое обучение, высокая стабильность |
| | **XGBoost Regressor** | **0.35** | **0.39** | 🏆 **Лучший результат (минимальная ошибка)** |

> [!NOTE]
> Применение ансамблей (Random Forest, Gradient Boosting, CatBoost, XGBoost) позволило снизить ошибку прогнозирования почти на **28%** по сравнению с базовой линейной регрессией. Лучший результат показал **XGBoost** с валидационным скором **0.39**.

## 🚀 5. Как запустить проект локально

### Шаг 1. Клонирование репозитория
```bash
git clone https://github.com/ВАШ_НИКНЕЙМ/nyc-taxi-trip-duration.git
cd nyc-taxi-trip-duration
```

### Шаг 2. Настройка виртуального окружения и установка зависимостей
```bash
python3 -m venv venv
source venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

### Шаг 3. Загрузка данных
> [!IMPORTANT]
> Из-за ограничений GitHub на размер файлов (>100MB), тяжелые CSV-файлы были добавлены в `.gitignore` и отсутствуют в репозитории.
1. Скачайте исходный тренировочный и тестовый наборы данных с [Kaggle New York City Taxi Trip Duration](https://www.kaggle.com/c/nyc-taxi-trip-duration/data).
2. Создайте в корне проекта директорию `data/`.
3. Поместите туда скачанные файлы, а также сопутствующие файлы OSRM и метеоданных (`weather_data.csv`, `holiday_data.csv`, `osrm_data_train.csv`).

### Шаг 4. Запуск Jupyter Notebook
```bash
jupyter notebook
```
Откройте файл `NYC_Taxi_Trip_Duration.ipynb` и запустите ячейки.
