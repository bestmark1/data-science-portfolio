# 01. Классификация качества красного вина (SVM)

Бинарная классификация: по 11 физико-химическим свойствам красного вина определить, «хорошее» оно или нет.

**Файлы:** [`wine_quality_classification.ipynb`](wine_quality_classification.ipynb) · [`winequality-red.csv`](winequality-red.csv)

## Задача

Экспертная оценка вина (`quality`, шкала 0–10) субъективна и дорога. Нужно предсказывать её по лабораторным измерениям. Исходную оценку превращаем в два класса:

| Класс | Условие | Доля в данных |
|-------|---------|---------------|
| `bad wine` (0) | `quality` ≤ 6 | 86.4% (1382 вина) |
| `good wine` (1) | `quality` ≥ 7 | 13.6% (217 вин) |

## Данные

Wine Quality (красное вино, португальское Vinho Verde), UCI Machine Learning Repository, Cortez et al., 2009. Лицензия CC BY 4.0.

- 1599 наблюдений, 11 признаков + `quality`
- Признаки: `fixed acidity`, `volatile acidity`, `citric acid`, `residual sugar`, `chlorides`, `free sulfur dioxide`, `total sulfur dioxide`, `density`, `pH`, `sulphates`, `alcohol`
- Пропусков нет; полных дубликатов строк — 240 (не удалялись, см. «Ограничения»)

## Методология

1. **EDA:** распределение `quality`, гистограммы всех признаков, корреляции с `quality`. Сильнее всего связаны `alcohol` (+0.48), `volatile acidity` (−0.39), `sulphates` (+0.25).
2. **Целевая переменная:** бинаризация по порогу 6.5, кодирование `bad wine → 0`, `good wine → 1`.
3. **Разбиение:** train/test 80/20, `stratify=y`, `random_state=42` (1279 / 320 объектов).
4. **Pipeline:** `StandardScaler` → `SVC`. Масштабирование внутри Pipeline, поэтому на кросс-валидации оно обучается только на train-фолдах.
5. **Подбор гиперпараметров:** `GridSearchCV` (76 комбинаций × 5 фолдов = 380 обучений) по `accuracy`, разбиение `StratifiedKFold(n_splits=5, shuffle=True, random_state=42)`. Перебирались ядра `linear`, `rbf`, `poly`, `sigmoid`, `C ∈ {0.1, 1, 10, 100}`, `gamma ∈ {0.001, 0.01, 0.1, 1, scale, auto}`.
6. **Оценка:** лучшая модель проверена на отложенной тестовой выборке.

## Результаты

Лучшие параметры: `kernel='rbf'`, `C=10`, `gamma=1`.

| Метрика | Значение |
|---------|----------|
| Accuracy, кросс-валидация на train (GridSearchCV) | **0.891** |
| Accuracy, test (320 объектов) | **0.922** |

Confusion matrix на test (строки — факт, столбцы — прогноз):

|  | предсказано `bad` | предсказано `good` |
|--|-------------------|--------------------|
| факт `bad` | 274 | 3 |
| факт `good` | 22 | 21 |

Classification report на test:

| Класс | precision | recall | f1-score | support |
|-------|-----------|--------|----------|---------|
| bad wine | 0.93 | 0.99 | 0.96 | 277 |
| good wine | 0.88 | 0.49 | 0.63 | 43 |
| macro avg | 0.90 | 0.74 | 0.79 | 320 |

## Как читать результат

- Классы несбалансированы: модель, которая всегда отвечает `bad wine`, получила бы accuracy около 86%. Поэтому 92% accuracy — умеренное улучшение, а не «почти идеал».
- Модель осторожна: хорошие вина находит с precision 0.88, но recall всего 0.49 — примерно половина хороших вин уходит в `bad`. Если важнее не пропустить хорошее вино, стоит оптимизировать `recall`/`f1` для класса `good` (или `class_weight='balanced'`), а не `accuracy`.

## Ограничения и что можно улучшить

- **Дубликаты:** 240 повторяющихся строк не удалены, часть из них могла попасть и в train, и в test — оценка на test может быть слегка завышена.
- **Финальная кросс-валидация на всём датасете:** в конце ноутбука `cross_val_score` (среднее 0.905, std 0.009) считается на всех 1599 объектах, включая test, хотя гиперпараметры подбирались на train. Как независимая оценка это число надёжно не читается; ориентироваться стоит на test accuracy.
- **Метрика подбора:** `accuracy` при дисбалансе — не лучший выбор; проверить `f1`/`balanced_accuracy`/`PR-AUC`.
- **Сравнение с другими моделями:** логистическая регрессия, Random Forest, градиентный бустинг — как baseline.
- **Порог 6.5:** результат зависит от границы между классами.
