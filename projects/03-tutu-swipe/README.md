# 03. tutu-swipe — свайп-подбор путешествий ⭐

**Код и документация:** [bestmark1/tutu-swipe](https://github.com/bestmark1/tutu-swipe) · **Демо:** [45.150.39.20:8030](http://45.150.39.20:8030)

Проект ИИ-хакатона Туту (август 2026). Это не ноутбук, а веб-приложение на TypeScript (Next.js), поэтому оно живёт в собственном репозитории; здесь — краткая карточка.

## Задача

Тревел-поиск работает, когда человек знает, куда едет. Фраза «хочу на море в сентябре, вдвоём из Москвы, тысяч за шестьдесят, чтобы не шумно» не превращается в поисковый запрос ни в одном сервисе. Проект принимает такую фразу и выдаёт ленту готовых поездок, которая учится на лайках и дизлайках.

## Как устроено

- Разбор свободной фразы правилами, без обращения к LLM на типичном запросе
- MCP Туту не умеет discovery (все инструменты требуют явный `destination`), поэтому подбор направлений построен на нашей стороне: каталог из 56 направлений и детерминированный отбор кандидатов
- Веерный параллельный поиск дорог и жилья, сборка поездок с итоговой ценой
- Скорость: предзаготовленный снапшот из 227 карточек отдаёт первую карточку за 17 мс, живые данные догоняют и заменяют её (холодный вызов MCP без снапшота — 10.8 с)
- Обучение на реакциях: байесовская линейная регрессия + Thompson sampling, причины дизлайков двигают веса

## Результаты

Оценка эффекта обучения (реакции разделены по времени, обучение на первых 70%, измерение на последних 30%):

| Режим | Средняя позиция лайкнутых карточек (меньше — лучше) |
|-------|------------------------------------------------------|
| Байесовская модель | 37.1 |
| Взвешенные правила | 45.8 |
| Сортировка по цене | 112.3 |
| Случайный порядок | 134.8 |

Ограничение, указанное в самом отчёте: проверочная выборка — девять лайков, преимущество модели над эвристиками не доказано, вывод предварительный.
