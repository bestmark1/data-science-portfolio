# Sales Time Series Forecasting

Учебный проект по анализу и прогнозированию временных рядов на датасете [Corporación Favorita Grocery Sales Forecasting](https://www.kaggle.com/competitions/favorita-grocery-sales-forecasting) (Kaggle) — от классической декомпозиции ряда до градиентного бустинга.

Единственный ноутбук [`sales_forecasting_project.ipynb`](./sales_forecasting_project.ipynb) полностью выполнен (все ячейки содержат реальный вывод и графики одного сквозного запуска).

## Содержание

1. **Магазин №25 — базовый анализ временного ряда**
   Загрузка `train.csv` по частям (`chunksize`, файл ~5 ГБ / 125 млн строк), группировка по дате, сезонная декомпозиция (`seasonal_decompose`), тест Дики-Фуллера, `TimeSeriesSplit`, скользящие статистики (среднее, стандартное отклонение, линии Боллинджера, EMA, кастомная скользящая функция, точки пересечения средних), лаговые признаки.

2. **Товар №103501 — ARMA/ARIMA**
   Тест Адфуллера, прогноз скользящим средним (окно 6), лаги 1–6, линейная регрессия на лагах, определение параметров `p`/`q` по ACF/PACF, модель ARIMA — сравнение метрик (MSE, MAE, MAPE).

3. **Общий объём продаж (все магазины и товары) — Prophet**
   Прогноз на 365 дней вперёд, подбор `changepoint_prior_scale`, добавление месячной сезонности, добавление праздничных дней (`data/holidays_events.csv`) — сравнение RMSE на каждом шаге.

4. **Общий объём продаж (все магазины и товары) — XGBoost и CatBoost**
   Признаки из даты (день недели, месяц, день года и т.д.), сравнение важности признаков, признак праздника (библиотека `holidays`, Эквадор), лаговые признаки с учётом ограничения «лаг ≥ размер тестовой выборки» — итоговое сравнение MSE/MAE/MAPE.

## Ключевые результаты

- Тест Дики-Фуллера подтвердил стационарность рядов и для магазина №25, и для товара №103501.
- В прогнозе Prophet на суммарных продажах наибольший прирост точности дало добавление **праздников** (RMSE снизился с ≈109 тыс. до ≈74 тыс.), а не тонкая настройка `changepoint_prior_scale` или сезонности.
- В сравнении XGBoost/CatBoost праздники также оказались самым полезным признаком; лаги ≥30 дней (по условию — не меньше горизонта прогноза), наоборот, немного ухудшили метрики обеих моделей.
- CatBoost на «сырых» календарных признаках без дополнительной настройки точнее XGBoost.

## Данные

- `train.csv` — основной датасет (~5 ГБ), **не входит в репозиторий** из-за размера. Скачайте его со страницы соревнования [Favorita Grocery Sales Forecasting на Kaggle](https://www.kaggle.com/competitions/favorita-grocery-sales-forecasting/data) и положите в корень проекта рядом с ноутбуком.
- `data/holidays_events.csv` — календарь праздников Эквадора, входит в репозиторий (используется в части 3).

## Как запустить

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
jupyter notebook sales_forecasting_project.ipynb
```

Так как `train.csv` читается по частям (`chunksize=5_000_000`), для полного прогона достаточно 16 ГБ RAM. Полный прогон ноутбука занимает около 3 минут.
